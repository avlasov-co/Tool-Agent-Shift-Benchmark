# Migrating to v0.4.0

v0.4.0 changes the evidence contract more than the public Python surface. The
safe migration is to preserve legacy bundles unchanged, rerun a schema-v2
configuration into a new named bundle, and consume the versioned records below.

## Package imports and CLI

Use `tool_agent_shift_benchmark` and the installed `tasb` command. Imports from
an old generic or checkout-relative package are unsupported. Packaged configs
and suites work outside a source checkout:

```bash
tasb config list
tasb suite list
tasb suite plan standard
```

## Configuration schema v2

All configs require `schema_version: 2`. Unknown keys, values, duplicate YAML
keys, malformed plugin references, and invalid split selections fail instead
of being ignored. `monitor_modes` selects detector composition;
`oversight_modes` independently selects enforcement. Use `tasb config migrate`
to print an explicit legacy-v1 migration and review every recorded decision.

## Identity v2

Scientific identity includes scenario generator/family/split, component
descriptors, shift schedules and severity, monitor composition, oversight
treatment, resource hashes, step semantics, and deterministic seed streams.
Operational controls such as workers do not define the scientific `run_id`.
The current wire value is `identity_schema_version: "20"`; it is the stable
serialized token for the v2 identity contract and must be treated as an opaque
version string, not parsed as the integer twenty.

## Plugin contract v2

Every environment, agent, shift, monitor, and evaluator has a validated
descriptor with version, contract version, implementation identifier,
configuration hash, trust level, capabilities, and isolation mode. Plugins may
receive policy-visible `ObservationContext` and `ToolResponse` only. They may
not read evaluator-only state or mutate unrelated files. A plugin exception is
an orchestration error, never a benchmark safety outcome. See the dedicated
[plugin migration guide](../development/plugin-v1-to-v2-migration.md).

## Run bundles and artifact schemas

`runs/<name>/` is the evidence boundary. `run_manifest.json` inventories every
artifact and SHA-256 checksum; `finalization.json` binds that manifest;
`status.json` keeps planned, completed, failed, pending, skipped, and invalid
counts visible. Verify before analysis or reporting:

```bash
tasb verify-run --strict runs/<name>
```

Key schemas are `run-bundle-v2`, `results-json-v2`, `results-csv-v2`,
`metric-schema-v2`, `statistical-analysis-v1`, `monitor-evaluation-v1`, and
`report-provenance-v1`. Do not deserialize scientific records with string
fallbacks or splice root-level legacy output into a new bundle.

## Agent and oversight factorization

An agent policy, monitor detector, and oversight treatment are independent
experimental factors. `record_only` observes but does not block;
`hard_gate` may alter execution. A threshold sweep is a simulated detector rule
and cannot be reported as an executed hard-gate treatment. Compare treatments
only when the execution plan shows that they ran.

## Scenario manifests and pairing

Each unique scenario has an immutable v3 manifest, family descriptor, content
hash, root/generator seed, split, and matched pair identifier. Development,
validation, and challenge indices occupy disjoint namespaces. The challenge
suite is held out: its outcomes may not be used to tune code, thresholds,
weights, claims, or defaults.

## Metric definitions

Read `results/metric_evidence.csv` rather than inferring denominators from old
summary columns. Planned episodes are the denominator for headline episode
rates; eligible completed action records are used for step rates; unsupported
counterfactual proposals are visibly ineligible. Constraint violation is
separate from generic unsafety. Temporal recovery requires a prior hazard,
later corrective behavior, and a later safe useful/successful state; abstention
alone is not recovery. Schema recovery is separate. The legacy
`safe_completion_rate` alias is not a v0.4.0 headline metric.

Uncertainty uses unique scenario manifests, stratified by scenario family, as
independent units. Repeated steps and treatment rows are not extra samples.
Shift effects use matched scenario pairs and report missing pairs. Any
insufficient cell has null bounds and an explicit status.
